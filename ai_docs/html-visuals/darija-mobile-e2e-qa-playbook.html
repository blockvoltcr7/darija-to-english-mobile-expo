Known good backend

Do not repeat the backend E2E unless the UI test fails.

Epic 03 already proved the authenticated server path: Clerk -> API -> Supabase Storage -> Trigger.dev worker -> Modal and OpenAI -> Supabase result rows -> polling success.

Purpose of this test

Confirm the mobile app launches, signs in, records or uploads audio, calls the async endpoint, renders progress, shows the English result, and can reopen history.

Why now

Epic 04 adds blocking controls. First prove the happy path, then add quota, rate limit, kill switch, retention, and deletion behavior.

Do not use Expo Go

This repo uses Clerk native auth and expo-dev-client. Use a development build for the real auth flow.

Fast first pass

Use Simulator first when you want to remove phone networking from the problem.

The iOS Simulator can reach the Mac API at localhost:8787. This is the fastest way to test Clerk, record/upload, polling, result render, history, and account screens.

Command

EXPO_PUBLIC_API_BASE_URL=http://localhost:8787 npm run ios
  • Sign in or sign up with a Clerk test user.
  • Grant microphone permission.
  • Record 3 to 8 seconds or upload a small audio file.
  • Expected status path: Recording -> Submitting -> Queued -> Running/Polling -> Complete.
Recommended real-device path

Install a development build on the iPhone. Then use QR to load Metro.

1

Plug in

Connect iPhone to MacBook by cable. Trust the computer. Enable iOS Developer Mode if prompted.

2

Same Wi-Fi

Put Mac and phone on the same network. Avoid guest/public Wi-Fi when possible.

3

Find LAN IP

Use the Mac Wi-Fi IP. The phone cannot use Mac localhost.

4

Install app

Run local iOS build with --device and select the connected iPhone.

5

Scan QR

Start Metro in LAN mode. Scan the QR with Camera to open the dev build.

Physical iPhone command set

Use the Mac LAN IP for the app API URL.

Get Mac LAN IP

MAC_LAN_IP=$(ipconfig getifaddr en0)
echo $MAC_LAN_IP
curl http://$MAC_LAN_IP:8787/health

If en0 is empty, check Wi-Fi/Ethernet in System Settings or inspect ifconfig.

Install on connected iPhone

EXPO_PUBLIC_API_BASE_URL=http://$MAC_LAN_IP:8787 \
  npx expo run:ios --device

This compiles and installs a debug development build. The cable is mainly for install/signing, not for API networking.

After the dev build exists

EXPO_PUBLIC_API_BASE_URL=http://$MAC_LAN_IP:8787 \
  npx expo start --dev-client --lan --clear

What the QR does

The QR points your installed dev build at Metro.

  • Install the development build first with npx expo run:ios --device or an EAS development build.
  • Start Metro with --dev-client --lan.
  • Scan the QR with the iPhone Camera app.
  • If it tries to open Expo Go, the dev build is not installed or the URL is not targeting the dev client.
  • If LAN fails, try npx expo start --dev-client --tunnel --clear, but keep API URL reachable from the phone.
Functional QA script

Run one clean translation from the actual app UI.

1

Auth

Sign up or sign in with a Clerk test user. Do not use production personal data.

2

Permission

Grant microphone permission when iOS asks.

3

Record

Record 3 to 8 seconds of simple speech, then stop.

4

Observe

Watch status move through submitting, queued, running or polling.

5

Verify

English Translation appears and diagnostics contain job/polling events.

Pass condition

The app reaches Complete within 180 seconds and displays English text. API logs should show authenticated request, async job queued, polling, and result retrieval.

Mobile surface checklist

Do not stop at the first translation result.

Home

  • Status pill changes correctly.
  • Record button toggles to Stop.
  • Upload Audio remains disabled during work.
  • Reset clears result and diagnostics.

Diagnostics

  • Health request appears.
  • Clerk token loaded without printing token.
  • Queued job ID appears.
  • Polling status appears.

History

  • Recent translation appears.
  • Status is succeeded.
  • Detail opens.
  • English and consolidated Arabic are visible.

Account

Open Account, confirm the signed-in email/user is correct, then verify Sign out returns to the Clerk auth screen.

Upload alternative

If recording is blocked by device setup, use Upload Audio with a small local audio file and run the same status/result/history checks.

Decision gate

Move to Epic 04 only after this checklist is green.

Go

  • iOS app launches in dev build.
  • Clerk sign-in or sign-up works.
  • API health succeeds from the target device path.
  • One record or upload translation completes.
  • History/detail shows the completed result.
  • Sign out returns to sign-in.

No-go

  • Phone cannot reach Mac API.
  • QR only opens Expo Go.
  • Clerk auth cannot complete.
  • Worker never receives the job.
  • UI completes but history is missing.
  • Any secret/token appears in copied evidence.
