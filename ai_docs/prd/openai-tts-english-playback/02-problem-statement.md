# 02 Problem Statement

## Current State

| Area | Current behavior | Evidence |
| --- | --- | --- |
| Upload | Expo sends `{ filename, audio_base64 }` to `POST /v1/translations`. | `lib/api.ts`, `server/index.mjs` |
| Auth | Mobile sends `Authorization: Bearer <Clerk session token>`. | `lib/api.ts`, `server/index.mjs` |
| Queueing | API stores original audio and dispatches `translate-audio-job`. | `server/index.mjs`, `trigger/translate-audio-job.mjs` |
| Processing | Trigger runs Modal Darija ASR and OpenAI STT, then OpenAI consolidation and translation. | `server/translation-pipeline.mjs` |
| Persistence | Text results persist in `translation_results`; provider calls persist in `provider_runs`. | `server/translations.mjs`, `supabase/migrations/20260510202655_create_translation_persistence_tables.sql` |
| Storage | Original audio is stored in private `audio-originals`; job rows include `artifact_bucket` and `artifact_prefix` metadata. | `server/storage.mjs`, `supabase/migrations/20260510222509_add_storage_metadata_to_translation_jobs.sql` |
| Results | Mobile polls `GET /v1/translations/:id` and maps text result fields. | `lib/api.ts`, `lib/types.ts`, `app/translate.tsx` |
| Playback | No generated English audio exists. | No `tts` or English audio fields in `lib/types.ts` or `server/index.mjs` result mapping. |

## The Gap

| Missing capability | Why it matters | Required change |
| --- | --- | --- |
| TTS provider call | The app cannot speak the completed English translation. | Add OpenAI TTS provider helper. |
| Generated audio artifact storage | Mobile needs a stable playback source without provider credentials. | Store generated audio bytes in private Supabase Storage. |
| Artifact metadata | API and UI need status, provider, model, voice, format, and error state. | Add `translation_artifacts` table or equivalent repository model. |
| Authenticated playback route | Storage object keys must remain private. | Add server-mediated download endpoint or signed URL generation. |
| Mobile result type | Client does not know whether audio exists. | Extend `TranslationResult` and `TranslationHistoryDetail`. |
| Playback UI | User has no Play control. | Add controls to `app/translate.tsx` and history detail. |
| Idempotency | Trigger retries could double-bill TTS. | Hash text/provider config and skip if matching artifact exists. |
| Failure isolation | TTS provider failures should not hide text translation. | Track TTS status separately from translation job success. |

## Key Differences Beyond The Obvious

- TTS is an artifact lifecycle, not just another field in `translation_results`.
- The backend must not expose OpenAI-generated bytes directly from the OpenAI response to Expo; it should store and serve them through app-controlled auth.
- Existing `provider_runs` only allows providers `openai` and `modal`, and operations do not include `openai_tts`; implementation must extend these checks if TTS provider runs are tracked there.
- `translation_jobs` already has `artifact_bucket` and `artifact_prefix`, but no per-artifact row. MVP should add a dedicated artifact table so multiple generated artifacts can coexist later.
- Translation success and TTS success need separate states so a user can still read the translation if audio generation fails.
