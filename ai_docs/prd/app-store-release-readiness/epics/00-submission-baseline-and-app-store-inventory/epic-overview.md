# Epic 00: Submission Baseline And App Store Inventory

## Goal

Freeze the current iOS App Store submission assumptions before implementation work starts. This epic prevents later legal, runtime, UI, and App Store submission tasks from relying on stale or implicit configuration.

## Scope

- Inventory `app.json`, `eas.json`, `package.json`, EAS channels, runtime version, and App Store Connect app ID.
- Decide production submit credential strategy without committing Apple credentials.
- Inventory production Clerk auth methods and decide whether Sign in with Apple is required.
- Confirm encryption export, tablet support, and EAS Update policy assumptions.
- Write a sanitized baseline evidence document.

## Tasks

1. `01-inventory-ios-config-and-runtime`
2. `02-decide-production-submit-and-credentials`
3. `03-inventory-clerk-auth-and-apple-sign-in`
4. `04-confirm-encryption-tablet-and-ota-policy`
5. `05-write-submission-baseline-evidence`

## Dependencies

- None.

## Exit Criteria

- Release owner has a sanitized app identity and native configuration baseline.
- Production submit strategy is explicit.
- Clerk auth methods and Sign in with Apple decision are recorded.
- Tablet, encryption, and OTA policy assumptions are documented before downstream work proceeds.

## Enriched Overview

### Scope

Epic 00 freezes the iOS App Store submission baseline before downstream implementation. It produces sanitized, owner-verifiable records for app identity, EAS build/submit lanes, production submit credentials strategy, Clerk auth methods and Sign in with Apple applicability, encryption export assumptions, tablet scope, and EAS Update policy. It must not create live App Store, Clerk, EAS, API, or production runtime evidence unless execution-time verification actually occurs.

| 02 | `decide-production-submit-and-credentials` | Infrastructure | Document the production iOS submit method, App Store Connect app ID handling, credential ownership, and safe future production build/submit command shape without committing Apple or EAS secrets. | Depends on Task 01; blocks Task 05 and Epic 05 production TestFlight submission. |

### Execution Notes

- Keep all execution evidence under task-local `artifacts/`; the support files added during enrichment are templates and source anchors only.
- Recheck live account state before relying on historical App Store Connect, TestFlight, Clerk, or EAS evidence. The TestFlight log and `eas.json` provide useful anchors, but account dashboards can drift.
- Preserve the iOS-only scope. Android, Google Play, and broader production expansion stay out of this epic unless the release owner explicitly widens scope.
- Production API/runtime remains a downstream no-go gate until `ai_docs/deployment/production-api.md` is superseded by verified production evidence.
- Never paste `.env` values, API keys, Clerk session tokens, Apple credential material, private account data, private audio details, full transcripts, or generated audio bytes into evidence.
- If any Task 01-04 artifact is missing or unaccepted by the release owner, Task 05 should mark Epic 00 blocked instead of manufacturing a ready baseline.
