# Task 02: Add OpenAI TTS Provider

## Type

Code

## Context

The MVP provider is OpenAI `gpt-4o-mini-tts`. The provider helper must run only in server or Trigger.dev contexts and return audio bytes plus safe metadata for storage and artifact lifecycle updates.

## Implementation

- Add `server/tts/openai-tts.mjs`.
- Create a helper that calls `client.audio.speech.create(...)` with model, voice, input, instructions, and `response_format`.
- Convert the returned array buffer to a Node `Buffer`.
- Reject empty English text before calling OpenAI.
- Apply a clear MVP behavior for overly long text: either cap/fail gracefully or prepare for later chunking, matching the PRD.
- Return safe metadata such as provider, model, voice, format, MIME type, byte size, and duration when available.
- Keep the raw OpenAI client response, API key, and generated bytes out of logs.

## Acceptance Criteria

- [ ] `server/tts/openai-tts.mjs` exists and passes `node --check`.
- [ ] Empty English text never triggers a provider call.
- [ ] OpenAI request uses server env config for model, voice, and response format.
- [ ] Helper returns an audio `Buffer` and safe metadata.
- [ ] Provider failures surface as safe errors suitable for artifact failure persistence.

## Dependencies

- Depends On: add-server-tts-env-contract
- Blocks: add-tts-provider-router-and-idempotency

## Technical Notes

- Use existing OpenAI client initialization patterns from the server pipeline where possible.
- The default instruction from the PRD is: `Speak clearly in a warm, neutral voice.`
- Avoid putting full English translation text in thrown errors or logs.

## Artifact Slots

- `artifacts/`: provider smoke-check notes and sanitized metadata examples.
- `references/`: OpenAI TTS request shape from the PRD and existing OpenAI usage in `server/translation-pipeline.mjs`.
- `resources/`: short non-sensitive sample English input for local smoke testing.
- `notes/`: text-length handling decision and provider error mapping.
