# Prepare Epic

Validate a local epic folder produced by `seed-epics` and refined by `enrich-epic`, initialize its `status.log`, regenerate the `epic-overview.md` status table, and create a checkpoint commit. This is the "prepare the task set" step that gates downstream analysis and execution.

Preferred task shape:

```text
<epic_folder>/<NN>-<slug>/task.md
```

Legacy task shape is still accepted:

```text
<epic_folder>/<NN>-<slug>.md
```

## Input

Parse one argument:
- `epic_folder_path`: path to the epic folder

If it is missing, ask for it.

## Workflow

### 1. Read the epic

Read `epic-overview.md` and every task spec in the folder.

Preferred discovery:
- glob `<epic_folder>/<NN>-<slug>/task.md`

Legacy discovery:
- glob `<epic_folder>/<NN>-<slug>.md`
- skip `epic-overview.md`, `*.plan.md`, and `status.log`

If both shapes exist for the same slug, prefer the folder task and warn about the legacy duplicate.

### 2. Validate structure

For each task spec, confirm the full enriched task contract exists:
- `## Type`
- `## Context`
- `## Implementation`
- `## Acceptance Criteria`
- `## Dependencies` (may be empty)
- `## Technical Notes`
- `## Artifact Slots`

If a required section is missing, hard fail with the file path and the missing section name. Do not proceed.

### 3. Validate enriched overview

Confirm `epic-overview.md` contains the enrichment-owned overview block:

```markdown
<!-- ENRICHED-OVERVIEW-START -->
...
<!-- ENRICHED-OVERVIEW-END -->
```

Hard fail if either marker is missing. Tell the user to run `enrich-epic <epic_folder_path>` before `prepare-epic`.

Do not validate or rewrite the content inside the enriched overview block beyond confirming the markers exist; `enrich-epic` owns that content.

### 4. Validate slugs

Compute each task's slug by stripping the `^\d+-` prefix from the task folder name for folder tasks:

```text
01-add-login/task.md -> add-login
```

For legacy flat tasks, strip the prefix and `.md` suffix:

```text
01-add-login.md -> add-login
```

If two task specs in this epic resolve to the same slug, hard fail unless one is a legacy flat duplicate of a folder task. In that case, prefer the folder task and warn that the legacy file should be removed or migrated.

### 5. Validate dependencies

Parse the `## Dependencies` section of each task. Each `Depends On: <slug>` must resolve to:
- An existing task spec in this epic (slug match), OR
- A `<other-epic>/<slug>` reference where the other epic folder exists at the same parent path and contains a matching slug in either task-folder or legacy flat shape

Detect cycles in the seed-time dependency graph using DFS coloring (WHITE/GRAY/BLACK). Hard fail on any dangling reference or cycle, showing the offending task and the unresolved or cyclic reference.

### 6. Initialize state

Check whether `status.log` exists in the epic folder:

- **If absent:** create it. Append one `nil->open` line for each task, all sharing the same ISO 8601 timestamp:

  ```
  2026-04-14T12:00:00Z setup-auth nil->open
  2026-04-14T12:00:00Z add-login nil->open
  2026-04-14T12:00:00Z add-logout nil->open
  ```

- **If present:** parse it. For each task spec in the epic, check whether its slug appears in the log. If not, append a new `nil->open` line for it (this handles re-runs after new tasks are added to the epic).

Never delete or modify existing log entries. The log is append-only.

### 7. Generate the overview status table

Compute the current status of each task by reading `status.log` (last entry per slug wins; entries sorted by timestamp, not file position).

Update `epic-overview.md`. Find the block delimited by `<!-- STATUS-TABLE-START -->` and `<!-- STATUS-TABLE-END -->`. If the markers are not present, append them at the end of the file along with the table. If they are present, replace everything between them.

Table format:

```markdown
<!-- STATUS-TABLE-START — generated by prepare-epic/run-epic-codex, do not edit by hand -->
| #  | Slug         | Type    | Status      | Updated              |
|----|--------------|---------|-------------|----------------------|
| 01 | setup-auth   | feature | open        | 2026-04-14T12:00:00Z |
| 02 | add-login    | feature | open        | 2026-04-14T12:00:00Z |
| 03 | add-logout   | feature | open        | 2026-04-14T12:00:00Z |
<!-- STATUS-TABLE-END -->
```

Anything outside the markers is human-owned and must not be touched.

### 8. Auto-commit

Stage the epic folder and create a commit. No prompt — auto-commit is required for this skill.

```bash
git add <epic_folder_path>
git commit -m "Prepare epic: <epic_name>"
```

Skip the commit only if `git status` shows no changes in the epic folder (idempotent re-run).

### 9. Handoff

Report:
- validation results (sections checked, enriched overview markers checked, deps resolved, cycles checked)
- task count
- new vs existing log entries
- next step: `analyze-epic <epic_folder_path>`

## Re-run behavior

Idempotent. Re-validates everything. Adds `nil->open` entries only for new tasks. Regenerates the overview table. Auto-commits only if there is a real diff.
