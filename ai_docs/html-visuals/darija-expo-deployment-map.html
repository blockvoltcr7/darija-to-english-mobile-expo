Darija to English production path

Expo builds the app. Your API still needs a real home.

The mobile app, the Express API, Trigger.dev worker, Modal ASR service, and Supabase data layer are separate runtime pieces. Expo can build and distribute iOS/Android binaries, and it can host web/API-route projects, but this repo currently uses a standalone Node/Express server that must be deployed separately or deliberately refactored into Expo Router API routes.

Phone beta testing exists

Use EAS internal distribution, TestFlight, or Google Play internal/closed testing before public release.

Expo is not your current API host

The current backend is server/index.mjs, launched with npm run api.

Production needs HTTPS URLs

EXPO_PUBLIC_API_BASE_URL must point to staging/prod API hosts, not localhost:8787.

Staging model

How to test before public rollout

Expo supports phone-installable beta paths. The right one depends on who is testing and how close to production you need to be.

Phase 01

Development build

Fast iteration
  • Best while coding and debugging.
  • Uses development client.
  • May still rely on local API or LAN API.
Phase 02

Preview internal build

Phone QA
  • Install through Expo build URL or QR.
  • iOS requires registered device UDID for ad hoc builds.
  • Android installs APK directly.
Phase 03

Store beta staging

Release candidate
  • iOS TestFlight.
  • Android internal or closed testing track.
  • Recommended staging path for near-production release checks.
Phase 04

Production release

Public users
  • App Store / Play Store public rollout.
  • Production API URL.
  • Production Trigger, Supabase, Clerk, Modal, and OpenAI config.
API hosting decision

Best backend component

There are two viable paths. The safer short-term choice is to deploy the existing Express API separately.

Recommended now

Deploy existing Express API to a Node host

Keep server/index.mjs intact and host it on a service that supports long-running Node/Express apps, environment secrets, logs, and outbound HTTP calls.

  • Lowest refactor risk.
  • Matches current Clerk Express middleware.
  • Works with current Trigger.dev and Supabase flow.
Later option

Refactor into Expo Router API routes

EAS Hosting can serve API routes when using +api.ts files and web.output = "server". This is not your current architecture.

  • Requires moving Express route logic into request handlers.
  • Runs on Cloudflare Workers/V8 isolates, not a full Node process.
  • May require changes for raw body, packages, and provider SDK compatibility.
The screenshot error is expected in a non-local deployment shape. The app is trying http://localhost:8787/health. On a physical phone or production build, localhost means the phone itself. You need a reachable HTTPS API URL.
