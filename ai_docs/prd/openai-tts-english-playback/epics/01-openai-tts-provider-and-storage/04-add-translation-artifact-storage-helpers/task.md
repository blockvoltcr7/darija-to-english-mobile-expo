# Task 04: Add Translation Artifact Storage Helpers

## Type

Code

## Context

Generated TTS audio must be stored in private Supabase Storage, not returned directly to the mobile app from the worker. Existing original-audio storage helpers live in `server/storage.mjs`; this task adds generated artifact storage behavior alongside that pattern.

## Implementation

- Update `server/storage.mjs` with `TTS_OUTPUT_FORMATS` or equivalent MIME mapping for `aac` and `mp3`.
- Add a safe object key builder for generated English audio under the `translation-artifacts` bucket.
- Add `uploadTranslationArtifact(...)` or equivalent to upload generated bytes with content type and ownership-safe pathing.
- Ensure object keys do not expose provider secrets, Clerk tokens, or full translated text.
- Return bucket, object key, byte size, MIME type, and format metadata for artifact success persistence.

## Acceptance Criteria

- [ ] Storage helper uploads generated TTS bytes to the private `translation-artifacts` bucket.
- [ ] Object keys are deterministic or traceable enough for support without leaking private text.
- [ ] MIME type and extension match the selected response format.
- [ ] Upload helper returns only safe storage metadata.
- [ ] Existing original-audio storage behavior remains unchanged.

## Dependencies

- Depends On: add-tts-provider-router-and-idempotency
- Blocks: run-tts-after-translation-success
- Blocks: add-authenticated-english-audio-route

## Technical Notes

- The PRD default format is `aac`, with `mp3` as a fallback if Expo playback compatibility requires it.
- Keep the bucket private. Playback access belongs in `server/index.mjs`, not Storage public policies.
